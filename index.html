A runtime for the part of JavaScript that runs in your browser.

ARCH.js is a small and actively developing project. It is experimental, package compatibility is still being worked on, and behaviour may change between releases.

Security stays within the browser.

ARCH.js runs client-side, so package code remains subject to the browser's normal security model. Third-party packages should still be treated as code you choose to execute and reviewed accordingly.

Compatibility is an ongoing part of ARCH.js.

ARCH.js is being developed around the wider JavaScript ecosystem. Compatibility varies by package, while support for libraries and tooling that expect different runtimes continues to expand.

FAQ

What is ARCH.js?
ARCH.js is a browser-side runtime and package loader for JavaScript projects. It is a small project and its APIs are still changing.
Is ARCH.js a replacement for Node.js?
No. ARCH.js is a separate browser-side runtime. Some Node.js-oriented packages work through its compatibility layer, but compatibility is incomplete.
How does package loading work?
ARCH.js resolves and prepares packages for browser use through its package-loading API. Support varies by package and is still expanding.
Is ARCH.js production ready?
ARCH.js is not stable or production-ready. Expect breaking changes as the runtime, APIs, and package compatibility continue to evolve.
Where can I see the source?
The source code, development history and current project status are available on GitHub.
