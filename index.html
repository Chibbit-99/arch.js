ARCH.js

JavaScript, but different.

A browser-side runtime and package loader for running more of the JavaScript ecosystem directly in the browser.

Why ARCH?

Browser JavaScript is great until you want to use packages. For small projects, setting up a complete package and build pipeline can be more work than the project itself. ARCH.js takes a different approach: load packages from the browser and keep the project simple.

Capabilities

Package loading

Load packages from the browser without setting up a traditional build pipeline.

await importPackage("tesseract.js");

Caching

Packages can be cached so repeated loads don't need to download everything again.

// cached after first load
await importPackage("three");

Browser-first

ARCH.js is designed around browser projects rather than trying to reproduce an entire Node.js environment.

// browser globals + packages
// without a Node.js runtime

Globals when needed

Packages that don't fit normal import behavior can expose selected exports.

await importPackage("biggames.js");
importGlobal("biggames.js", "PetSimulator99");

How it works

ARCH.js sits between your HTML and the package. It loads the runtime modules it needs, resolves packages, and prepares them for use by browser code.

Your HTML
↓
ARCH.js
↓
Package loader
↓
Package resolution
↓
Browser-compatible package

Less setup. More code.

Here's how small an ARCH.js project can be:

<script src="https://chibbit-99.github.io/arch.js/releases/latest.js"></script>

<script>
  await importPackage("three");

  // start building
</script>

That's it. No npm init. No webpack. No config.

Status

ARCH.js is currently v0.1.1-alpha. It is experimental software, and the API and architecture may change between releases.

Check the releases and GitHub for updates.
