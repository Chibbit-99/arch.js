ARCH.JS / DOCUMENTATION

Build a browser project with ARCH.js.

ARCH.js is a browser-side runtime and package loader. Load the runtime from a release file, describe your project in arch/config.json, optionally initialize dependencies in arch/init.js, and keep your application code in src/.

Quick start

Load the current ARCH.js development release from your HTML page.

<!doctype html>
<html>
<body>
    <h1>My ARCH.js app</h1>

    <script src="https://chibbit-99.github.io/arch.js/releases/latest.js"></script>
</body>
</html>

ARCH.js then looks for ./arch/config.json relative to the page.

my-project/
├── index.html
├── arch/
│   ├── config.json
│   └── init.js
└── src/
    └── main.js
The ARCH.js project itself does not require a package.json. Project startup is described through arch/config.json.

Project layout

index.html

Your webpage. Load ARCH.js with a script tag using a current or pinned release.

arch/config.json

Declares runtime modules and the project JavaScript files that ARCH.js should execute.

arch/init.js

Optional async setup code. Useful for loading packages or preparing globals before the application starts.

src/

Your application code. The js configuration can point to one file or several files.

Configure your project

A simple project can enable the bundled NPM loader and point ARCH.js at one entry file.

{
  "modules": ["npmloader.js"],
  "js": ["./src/main.js"]
}

modules

The modules array selects ARCH.js runtime modules. With npmloader.js enabled, your project gets the browser-side NPM package loader.

js

The js field selects the project files to execute. It accepts either one string or an array.

// One file
{
  "modules": ["npmloader.js"],
  "js": "./src/main.js"
}

// Several files
{
  "modules": ["npmloader.js"],
  "js": [
    "./src/components.js",
    "./src/main.js"
  ]
}

Use arch/init.js

arch/init.js is optional. When present, ARCH.js runs it before the files listed in config.json and waits for it to finish.

const three = await importPackage("three");

globalThis.THREE = three;

That makes init.js a convenient place for dependency setup that should happen once before the rest of the project runs.

Initialization is asynchronous, so await importPackage(...) can be used directly in arch/init.js.

Write your application

Your configured project files are normal browser JavaScript.

// src/main.js

console.log("ARCH.js is running");

document.body.insertAdjacentHTML(
    "beforeend",
    "<p>Hello from the project entry point.</p>"
);

When several files are configured, ARCH.js fetches them concurrently and executes them in the order listed by js.

Use NPM packages

Enable npmloader.js, then use importPackage() from your project code or arch/init.js.

const THREE = await importPackage("three");

const scene = new THREE.Scene();
console.log(scene);

The same approach is used by the repository's Three.js example.

importPackage()

await importPackage(specifier)
Loads a package and returns its module namespace. ARCH.js resolves the package, prepares it for browser use, and caches the result for reuse.
const three = await importPackage("three");
const tesseract = await importPackage("tesseract.js");

The function is exposed by the NPM loader and can be called directly once that module is enabled.

importGlobal()

importGlobal(packageName, exportKey, alias)
Places one export from an already imported package onto globalThis. The third argument is optional and lets you choose a different global name.
await importPackage("three");
importGlobal("three", "ArrowHelper");

// Optional alias
importGlobal("three", "Vector3", "Vec3");
The package must already be loaded. importGlobal() does not load the package itself.

Releases

Browser-ready ARCH.js builds live in the releases/ directory.

releases/
├── latest.js
├── v0.1.0-alpha.js
└── v0.1.1-alpha.js

releases/latest.js is the current development build. It can change as ARCH.js evolves.

For a stable reference to a particular release, use its versioned file instead:

<script src="https://chibbit-99.github.io/arch.js/releases/v0.1.1-alpha.js"></script>

Versioned release files are generated when a version tag is created, so projects can either follow the latest build or deliberately pin themselves to a specific release.

ARCH.js is currently at v0.1.1-alpha. It is still experimental software, and the API and architecture may change between releases.

Debugging

Open the browser developer console to see ARCH.js startup and package-loader messages. Runtime messages use the [ARCH] prefix.

const three = await importPackage("three");
console.log(three);

The runtime also exposes ARCH for inspection while debugging.

What ARCH.js handles

You provide the HTML page, project configuration, optional initialization, and application code. ARCH.js handles the runtime startup sequence and, when npmloader.js is enabled, the browser-side package loading needed to bring supported NPM packages into the project.
