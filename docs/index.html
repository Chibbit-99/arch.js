Documentation

ARCH.js is a browser-side JavaScript runtime and package loader. It is a small, experimental project: expect incomplete compatibility, rough edges, and breaking changes while the runtime is being built.

Development status: ARCH.js is not stable or production-ready. The APIs and package compatibility can change between releases.

Quick start

Load ARCH.js from your HTML page, then use importPackage() from a module script.

index.html 
<script src="https://chibbit-99.github.io/arch.js/releases/latest.js"></script>

<script type="module">
    const THREE = await importPackage("three");
</script>

By default, ARCH.js looks for ./arch/config.json relative to the page that loaded it.

Project layout

An ARCH.js project can stay small. The runtime configuration lives in an arch/ directory and your application code can remain ordinary browser JavaScript.

index.html
The page loaded by the browser.
arch/config.json
Selects runtime modules and project files.
arch/init.js
Optional asynchronous startup code.
src/
Application code executed by ARCH.js.

config.json

The configuration tells ARCH.js which runtime modules to load and which JavaScript files to execute.

arch/config.json 
{
  "modules": ["npmloader.js"],
  "js": ["./src/main.js"]
}

modules

The modules array selects runtime modules. The current project includes npmloader.js, which provides browser-side NPM package loading.

js

The js field can contain one file or an ordered array of files.

arch/init.js

arch/init.js is optional. When it exists, ARCH.js runs it before the configured project files and waits for the module to finish.

arch/init.js 
export const THREE = await importPackage("three");

Exports from arch/init.js are made available to the project runtime. This is the pattern used by the Three.js example.

Packages

With npmloader.js enabled, packages can be imported directly from project code.

src/main.js 
const THREE = await importPackage("three");

const scene = new THREE.Scene();

console.log(scene);

ARCH.js resolves the package, prepares it for browser use, handles its package files and dependencies, and returns a module namespace.

Versioned requests and package subpaths are also supported where the package can be compiled successfully.

package variants 
await importPackage("three@0.180.0");
await importPackage("some-package/helpers");
await importPackage("some-package@1.2.3/helpers");

API

await importPackage(specifier)
Loads a package and returns its module namespace. Loaded packages can be reused from the cache.
importGlobal(package, export, alias)
Places an export from an already imported package on globalThis. The alias is optional.
API example 
await importPackage("three");

importGlobal("three", "Vector3");
importGlobal("three", "ArrowHelper", "Arrow");

importGlobal() does not load a package. Import the package first.

Releases

Browser-ready builds live in releases/. latest.js tracks the current development build, while versioned files are tied to a specific release.

release files 
releases/
├── latest.js
├── v0.1.0-alpha.js
└── v0.1.1-alpha.js

For reproducible deployments, use a versioned release instead of latest.js.

Current status: experimental / unstable.

Debugging

Open the browser developer console to inspect ARCH.js messages. Runtime messages use the [ARCH] prefix.

console 
const THREE = await importPackage("three");

console.log(THREE);
console.log(ARCH);

The global ARCH object can be inspected while debugging. Package-loading failures and compilation errors are reported in the console.
